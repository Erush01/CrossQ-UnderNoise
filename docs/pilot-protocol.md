# HumanoidStandup 100k resource/stability pilot

## Purpose and scope

This is a bounded resource and stability check, **not full performance reproduction**. The only authorized run is `HumanoidStandup-v4`, seed `0`, exactly `100,000` environment steps, using SB3-Contrib CrossQ `2.9.0`, the paper-like settings including a `[2048, 2048]` critic and 100,000-step BRN warm-up, and `device=auto`. Evaluation follows the modern manifest protocol: every 25,000 steps, 20 episodes, across 5 evaluation environments. The user-approved 100k budget just reaches the paper's BRN warm-up threshold; it is not a substitute for the paper's 5M-step results.

## Preflight and thresholds

`scripts/run_pilot.sh --dry-run` first checks that the target does not exist, then runs `scripts/preflight_pilot.py`. It uses `$CROSSQ_PYTHON` when supplied, otherwise the read-only `../ARS/.venv/bin/python` runtime. Preflight creates and closes the configured Gymnasium environment to inspect observation/action shapes; estimates float32 replay storage as `capacity * (2 * observation elements + action elements + 2) * sizeof(float32)` because SB3 stores observations and next observations; requires available RAM of at least 1.5 times that estimate and free disk of at least the estimate plus 5 GiB. If auto-device can use CUDA, at least 2 GiB free CUDA memory is required and recorded; CPU fallback is acceptable when CUDA is unavailable. Any resource threshold failure or inability to instantiate the environment blocks execution. Preflight JSON and console logs are uniquely named, retained in `artifacts/logs`, and never overwrite prior files.

## Run and early-stop conditions

The original `HumanoidStandup-seed0` attempt stopped incomplete at 50,000 steps and is preserved unchanged. The user explicitly authorized exactly one fresh 100,000-step attempt from scratch, selected only with `scripts/run_pilot.sh --attempt2` (or `--dry-run --attempt2`) and written to `artifacts/pilot/HumanoidStandup-seed0-attempt2`. Attempt 2 does not resume or reuse the original run. Default invocation continues targeting the original path and refuses because it already exists. This is the sole authorized fresh attempt: no further automatic retries or resumes are allowed. Normal invocation runs exactly the one task/seed/budget. The run is not retried, its budget is never increased, and failures are not automatically resumed. Stop/abort before launch if preflight fails or the selected target exists. Stop the pilot on out-of-memory, device/runtime failure, corrupted artifacts, or an explicit user stop; preserve logs and partial outputs for diagnosis and do not automatically rerun. `/usr/bin/time -v` resource statistics and stdout/stderr are stored in unique `artifacts/logs` files.

## Review and consent gate

The operational acceptance target is completion within four hours; it is a review target only and does not impose an automatic timeout or kill. `scripts/summarize_pilot.py --validate-only <run-dir>` rejects incomplete or mismatched outputs, including a wrong step count, evaluation schedule or shape, non-finite metrics, invalid config/versions/hashes, or a checkpoint that fails to load with two `[2048, 2048]` critics. A completed review reports runtime and four-hour target status, available maximum RSS, evaluation reward/length curves, config/source hashes, package versions, resolved device, checkpoints, and deviations. Do not interpret this short pilot as a benchmark result. The full 5M-step × six-task × ten-seed benchmark remains gated: obtain explicit user consent before creating or launching any full benchmark workload.
